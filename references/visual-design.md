# 精细画面的制作方法

## 先建立可读布局

以 1280×720 为基准时，可从 40–56px 外边距、32–42px 标题、20–28px 主要标注、16–20px 辅助文字起步；它们是设计起点，不是所有画幅通用的固定参数。先在最终观看尺寸检查，不能靠提高导出分辨率补救过小文字。密集机制分镜拆开，而不是一味缩小字号。

把画布分为主体、说明/图例、字幕区域。主体应占主要视觉空间，标签按结构对齐并保留引线长度；不让引线穿过标题、运动通道和不相关对象。保留的空白应帮助分组。阶段提示按实际机制使用，非所有主题都需要四张卡片。

配色先规定角色：背景/结构/主过程/反过程/警示或未知。通常一个主色与一个强调色足够，色相与明度都需可区分；用形状、符号和文字补充颜色。相同实体跨阶段保持颜色，不能为了美观让颜色语义变化。

## 从几何正确到细节

先画结构轮廓并放大看接缝，再加填色/材质。圆角层层嵌套时共享圆心、按壁厚减少半径；封闭边界使用连续路径或裁切，不用不同圆角的色块硬拼。检查曲线切线、端帽、边框接合、遮挡次序和画布边缘。

外框、内部边界、辅助线采用有限层级的线宽，例如 1.5–2.5 / 0.8–1.2 / 0.6–1px；按目标像素尺寸调整。圆角线帽适合流动与柔性对象，尖角则保留在确有方向/结构意义的位置。剪切边界必须与看得见的结构一致，裁切不能用来掩盖科学上错误的路径。

细纹理、柔和色区、高光可说明材质或区域，不能盖住机制。细节应在缩放后仍干净；过密纹理在视频压缩后闪烁时优先减密或提高对比层次。不要默认使用重阴影、霓虹光效、厚实巨箭头或装饰性三维挤出。

## 让动作承担解释

先确定因果事件和状态，再安排运动。位移用于输运，形变用于变形，透明度用于显隐，颜色用于明确的状态变化。只有机制需要速度/相位变化时才加速，不能每个对象都不停运动。

路径运动默认有限数量、可辨间距、错开相位；循环的入口/出口用淡入淡出。不要让固定方向箭头和粒子堆在同一轨迹。结合、接触和相变可以有意相交，但必须在分镜说明，并为相应元素分别选择 `collisionGroup`；不能为了通过检查把所有碰撞组删掉。

时间分为进入、解释、停留与转场；标签尽量稳定，重要状态留出阅读时间。分镜切换前后检查是否有闪帧、对象突然复制/消失、字幕提前泄露尚未发生的结果。默认保持暂停，用户主动播放。

## 两层验收

技术层：结构合法、离线可运行、完整时间轴无未解释的碰撞、播放控制有效、视频完整解码。`audit_animation.mjs` 保存关键帧和机器检查结果；不能凭“编码成功”评判美观。

视觉层：打开实际关键帧，检查起始、最密集、状态切换前后、结束，以及至少两处结构边缘的放大细节。回答：第一眼能否看到主体？因果是否清楚？字是否读得清？轮廓和接缝是否连续？运动是否穿越不该穿越的结构？色彩/线宽/空间是否一致？

存在裁切文字、未解释的实体互穿、错误箭头、突兀接缝等问题时修订源文件并重建。审美有主观部分，可以描述已做的检查，不承诺所有领域、任意输入都一次成功。

## 不把制作缓存当成品

每次任务使用单独输出目录。视频帧通过管道送入 FFmpeg，不落地数百张 PNG。关键帧只在验收期间保留，最终选择一张预览；清除本次已确认无用的中间文件。浏览器在 finally 中关闭，不动用户现有浏览器配置和共享缓存。保留源文件与用户要求保留的历史版本。
